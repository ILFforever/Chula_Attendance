What it does

One link in, everyone checked in.

01

Automatic check-in

The bot watches your monitored channel. The moment a real MyCourseVille attendance link appears, it logs in as every registered student and clicks through — no one has to open the app, find the link, or race a countdown timer.

02

Only your courses

/enroll 2110405 and that's it — you'll only be checked into that course's links from then on, using the same public course code you already know from registration. No internal IDs to guess.

03

A fair leaderboard

/leaderboard tracks who's fastest to post the link. Reposting the same link or spamming stale ones doesn't inflate the score — credit only counts once, and only if a real check-in actually happened.

04

Encrypted by default

Credentials are encrypted at rest with Fernet (AES-128 + HMAC) the moment you /register. Every command response about your account is visible only to you.

05

Built to stay light

No headless browser, no Selenium, no Chrome process per user. Just plain HTTP requests and HTML parsing — the whole bot runs comfortably inside a 256MB container.

Getting started

Four steps and you're done.

1

Add to Discord

Add the bot to your server — anyone in the server can do this, not just admins.

2

/register

Save your MyCourseVille login — CU Net or platform account. Encrypted immediately, visible only to you.

3

/monitor

Point the bot at your class channel. It'll quietly watch for attendance links from then on.

4

Post the link

Whoever sees it first drops it in the channel. Everyone enrolled gets checked in within seconds.

/homework on

Pick a time with /homeworktime <hour> — default 8am Bangkok time.

2

Each course, its own message

Red, yellow, or green by how soon it's due. An Open in web button and a Mark as finished button sit right under every item.

You'll always know where you stand.

Every check-in sends you a personal DM with your result — so you're never left guessing whether it actually worked.

And if something does go wrong, it says so in plain language instead of quietly failing.

  • Wrong password? It tells you right away, instead of failing silently every class
  • Not in that course? You're skipped — no false alarms
  • Link already expired? You'll see that, not a fake "success"
  • Want to test it beforehand? /logincheck confirms your login works

Your credentials

How your password is handled.

Encrypted the moment you send it

Your password is encrypted with Fernet (AES-128 with an HMAC signature) before it ever touches disk. It's never written down in plain text, and the /register response is visible only to you — nobody else in the server sees it.

The key is kept apart from the data

Encrypted credentials live on the server's storage volume; the key that unlocks them is held separately as a hosting secret. Someone who got hold of the data file alone would find it useless.

Used for one thing only

Your login is used to sign into MyCourseVille and mark you present — nothing else. No analytics, no third parties, no other sites. The entire source is public, so you don't have to take that on faith.

The honest limit

The bot itself never displays, logs, or exports a stored password. But whoever operates the server can reach both the stored data and the key that unlocks it — that's unavoidable for any bot that signs in on your behalf, this one included. Using it means trusting the person running it. If you'd rather not, run your own copy — then that person is you.

Run your own

Want your own private instance?

The public bot is a single shared instance. Everyone who adds it shares one pool of registered users and one global leaderboard — so /users and /leaderboard show people from other servers too, and a link posted anywhere checks in everyone registered for that course.

For most class group chats that's fine. If you'd rather keep your members and rankings to yourselves, run your own copy — it's the same code, and you hold the only key to your own data.
